从零理解 PLAN B / C / D 与全身外轮廓光晕：Three.js 机器人特效实现路径 ​

这篇文档面向 Three.js 初学者。目标不是只解释“看起来是什么效果”，而是把当前项目里 PLAN B、PLAN C、PLAN D 三套选中部件效果，以及新增的全身外轮廓光晕，拆成可以复用的技术路径：

  • PLAN B：surface-particles，表面采样粒子层。
  • PLAN C：blueprint-shell，贴在原模型表面的蓝图 overlay。
  • PLAN D：particle-reconstruct，实体 dissolve + 星点粒子重构。
  • 全身外轮廓光晕：outerHaloEffect，基于机器人整体 silhouette 的 screen-space bloom 光晕。

配套 demo：

  • docs/public/demos/plan-bcd-effects-demo.html

这个 demo 是一个单文件 Three.js 示例，可以直接打开，也可以用任意静态服务器访问。它不依赖 Astro，不加载项目机器人模型，而是用基础几何模拟“被选中部件”和“全身轮廓”。项目真实代码更完整，demo 保留核心算法路径，方便你学习。

1. 共同基础：先把“选中部件”变成可计算数据 ​

Three.js 里的模型通常是一个树状结构：

txt
Scene
  Group
    Mesh head_A
    Mesh head_B
    Mesh face
    Mesh chest_front

项目里 SDK 或工具栏会先确定当前选中部件，例如 head、chest。然后根据配置表找到对应 mesh 列表：

ts
nodeNames: ["head_B", "head_A", "face"]

之后三套效果都不是“凭空画在屏幕上”，而是围绕这些 mesh 做事：

ts
effect.setMeshes(activePartMeshes)

可以把每个效果理解成一个独立渲染层：

txt
选中部件 meshes
  -> PLAN B: 生成 Points 粒子层
  -> PLAN C: 生成 Mesh overlay 层
  -> PLAN D: 修改原 mesh 材质 + 生成 Points 星点层

坐标空间是第一道坎 ​

Three.js 里常见两个坐标空间：

  • local space：geometry.attributes.position 里的点，属于单个 mesh 自己。
  • world space：乘上 modelMatrix 后的位置，属于整个场景。

如果一个部件由多个 mesh 组成，比如头部有 head_A、head_B、face，那么“从下到上整体扫过去”必须用 world space 计算。否则每个 mesh 都用自己的 local range，就会出现多个子网格各扫各的，看起来像分成多段同时分解。

PLAN D 修复后的关键点就是：整个选中部件共用一个 world-space uBuildRange。

2. 表面采样：PLAN B 和 PLAN D 的粒子从哪里来 ​

粒子不是随机撒在包围盒里，而是沿模型表面生成。项目里的核心工具是：

ts
createSurfaceParticleSamples(mesh.geometry, {
  density,
  maxParticles,
  seed,
})

它做了四步。

2.1 收集三角形面积 ​

模型表面由很多三角形组成。先遍历 index buffer 或 position buffer，把每个三角形的面积算出来：

ts
area = length(cross(b - a, c - a)) * 0.5

然后记录累计面积：

txt
triangle 0 cumulativeArea = 0.12
triangle 1 cumulativeArea = 0.31
triangle 2 cumulativeArea = 0.88

这样可以按面积加权抽样。面积大的三角形获得更多粒子，面积小的三角形获得更少粒子。

2.2 用重心坐标在三角形内取点 ​

随机选中一个三角形后，用重心坐标生成表面点：

ts
const r1 = Math.sqrt(random())
const r2 = random()
const a = 1 - r1
const b = r1 * (1 - r2)
const c = r1 * r2

point = A * a + B * b + C * c

这里使用 Math.sqrt(random()) 是为了让三角形内分布更均匀。直接用两个普通随机数会让点偏向某些区域。

2.3 同步插值 normal、size、seed ​

每个粒子至少需要这些 attribute：

ts
position        // 粒子贴在哪个表面点
aSurfaceNormal  // 表面法线，用来向外偏移
aSize           // 每个粒子的基础大小
aSeed           // 随机种子，驱动闪烁、漂移、相位

真实项目还会携带：

ts
aCageIndex
aCageWeight
aMoveStrength

这是为了配合晶格变形工具。初学阶段可以先理解为：粒子要跟着被编辑后的表面一起动。

2.4 塞进 BufferGeometry ​

最后把采样结果写入 BufferGeometry：

ts
geometry.setAttribute("position", new Float32BufferAttribute(positions, 3))
geometry.setAttribute("aSurfaceNormal", new Float32BufferAttribute(normals, 3))
geometry.setAttribute("aSize", new Float32BufferAttribute(sizes, 1))
geometry.setAttribute("aSeed", new Float32BufferAttribute(seeds, 4))

这一步完成后，CPU 侧的点已经准备好。每帧怎么漂、怎么亮、怎么显隐，交给 shader。

3. PLAN B：Surface Particles 表面粒子层 ​

PLAN B 的目标是：选中部件表面覆盖一层可呼吸、可 hover 流动、可从散到贴合的粒子壳。

它不是替换原 mesh，而是给每个 mesh 额外挂一层 THREE.Points：

txt
source mesh
  original material 继续显示
  points layer       叠在表面上

3.1 CPU 侧结构 ​

真实项目的 RobotSurfaceParticleEffect 里，每个 mesh 会对应一个 layer：

ts
type SurfaceParticleLayer = {
  sourceMesh: Mesh
  points: Points
  geometry: BufferGeometry
  buildRange: Vector2
}

每帧要同步 source mesh 的 world matrix：

ts
points.matrix.copy(sourceMesh.matrixWorld)
points.matrixWorld.copy(sourceMesh.matrixWorld)
points.visible = sourceMesh.visible

为什么要这么做？因为粒子的 position 存的是 mesh local space 表面点。Points 使用和 source mesh 一样的矩阵，就能贴回原来的世界位置。

3.2 吸附生成：build progress ​

PLAN B 第一次出现时，粒子不是立刻贴在表面，而是从“悬浮散开”吸附回来。

关键变量：

ts
uBuildAttachProgress // 0 -> 1
uBuildAxis           // 生成推进方向
uBuildRange          // 选中部件在该方向上的范围

shader 里把粒子位置投影到 build axis 上：

glsl
float buildCoord = clamp(
  (dot(transformed, uBuildAxis) - uBuildRange.x) / buildRangeSize,
  0.0,
  1.0
);

然后根据当前前沿位置算吸附程度：

glsl
float buildFront = mix(-uBuildBandWidth, 1.0 + uBuildBandWidth, uBuildAttachProgress);
float buildDistance = buildCoord - buildFront;
float attachAmount = 1.0 - smoothstep(-uBuildEdgeSoftness, uBuildBandWidth, buildDistance);
float looseAmount = 1.0 - attachAmount;

你可以这样理解：

txt
attachAmount = 0  粒子还没贴上去，比较散
attachAmount = 1  粒子已经贴回表面
frontBand         正在生成的亮边

3.3 常态漂移：normal + tangent ​

粒子要贴着表面，但不能死板。所以 shader 会构造局部切线方向：

glsl
vec3 worldNormal = normalize(mat3(modelMatrix) * aSurfaceNormal);
vec3 tangentA = normalize(cross(worldNormal, stableAxis));
vec3 tangentB = normalize(cross(worldNormal, tangentA));

然后叠加三个方向的运动：

glsl
worldPos += worldNormal * uSurfaceOffset;
worldPos += (tangentA * driftA + tangentB * driftB) * uDriftScale;
worldPos += worldNormal * looseAmount * uBuildSuspendLift;

这就是 PLAN B 的“贴在表面又轻微活着”的感觉。

3.4 Hover 流动 ​

CPU 侧用 Raycaster 找鼠标命中的表面点：

ts
raycaster.setFromCamera(pointer, camera)
const hit = raycaster.intersectObjects(meshes, false)[0]

然后记录：

ts
uHoverPoint     // 鼠标命中的世界坐标
uHoverDirection // 鼠标移动方向投影到表面切线
uHoverStrength  // 0 -> 1 平滑进入/退出

shader 里根据粒子到 hover point 的距离决定影响强度：

glsl
float hoverDistance = length(worldBase - uHoverPoint);
float hover = uHoverStrength * (1.0 - smoothstep(0.0, uHoverRadius, hoverDistance));
float hoverCore = hover * hover;

然后让粒子沿三个方向动：

glsl
worldPos += worldNormal * hoverCore * uHoverLift;
worldPos += hoverFlowDirection * hoverCore * uHoverFlow;
worldPos += viewPullDirection * hoverCore * uHoverCameraLift;

uHoverCameraLift 是“放大感”的主参数，因为它把粒子朝相机方向拉近。

3.5 扫光 ​

吸附完成后，PLAN B 会有一条循环移动的亮带：

ts
uLightSweepProgress = ((elapsed - attachDuration) / sweepDuration) % 1

shader 里计算当前粒子离亮带有多远：

glsl
float lightSweepDistance = min(
  abs(buildCoord - uLightSweepProgress),
  min(abs(buildCoord - uLightSweepProgress - 1.0), abs(buildCoord - uLightSweepProgress + 1.0))
);

float lightSweep = uLightSweepStrength *
  (1.0 - smoothstep(0.0, uLightSweepBandWidth, lightSweepDistance));

这条亮带不改变几何，只改变粒子位置、大小、颜色和 alpha。

3.6 PLAN B 常见难点 ​

  1. 粒子太密会卡。

密度不是唯一限制，还要有总上限：

ts
maxTotal = 42000
maxPerMesh = maxTotal / meshCount
  1. 点大小需要考虑相机距离。

如果只写固定 gl_PointSize，远近会很不稳定。项目里用 projection matrix 和 viewport height 做补偿。

  1. 粒子要避免遮住模型。

PLAN B 使用：

ts
depthTest: true
depthWrite: false
transparent: true

这样粒子能被前方模型遮挡，但不会把后续透明对象的深度写死。

4. PLAN C：Blueprint Shell 蓝图覆盖层 ​

PLAN C 和 PLAN B/D 最大区别是：它不生成粒子。它复制一层透明 mesh overlay，直接使用原 mesh 的 geometry。

txt
source mesh geometry
  -> overlay mesh
  -> ShaderMaterial

4.1 为什么用 overlay mesh ​

如果直接改原 mesh 材质，就会影响原来的白色机器人外观。PLAN C 想要的是“原模型还在，上面叠一层蓝图/能量/网格视觉”。所以它创建新的 mesh：

ts
const overlay = new Mesh(sourceMesh.geometry, blueprintMaterial)
overlay.matrixAutoUpdate = false
overlay.renderOrder = 22

每帧同步矩阵：

ts
overlay.matrix.copy(sourceMesh.matrixWorld)
overlay.matrixWorld.copy(sourceMesh.matrixWorld)

材质配置重点：

ts
transparent: true
depthTest: true
depthWrite: false
polygonOffset: true
polygonOffsetFactor: -2
polygonOffsetUnits: -2

polygonOffset 是为了减少 z-fighting。因为 overlay 和 source mesh 用的是同一份 geometry，如果深度完全一样，表面会闪烁。

4.2 自动选择 build axis ​

PLAN C 会看当前选中部件的世界包围盒：

ts
partBox = union(meshWorldBoxes)
size = partBox.getSize()

哪个轴最长，就沿哪个轴推进：

ts
if (size.y >= size.x && size.y >= size.z) axis = Y
else if (size.x >= size.z) axis = X
else axis = Z

这样手臂、腿、胸甲都能有比较自然的铺开方向。

4.3 Vertex shader 做什么 ​

PLAN C 的 vertex shader 主要输出这几个 varying：

glsl
vBuildWorldPos // 世界坐标，用于 procedural grid/noise
vBuildNormalW  // 世界法线，用于 rim light 和 triplanar
vBuildViewDir  // 视线方向，用于轮廓光
vBuildCoord    // 0-1 的生成进度坐标

核心还是这一句：

glsl
vBuildCoord = clamp((dot(worldPos.xyz, uBuildAxis) - uBuildRange.x) / buildRangeSize, 0.0, 1.0);

4.4 Fragment shader 做什么 ​

PLAN C 的 fragment shader 由几个图案函数组成：

glsl
planBlueprintShell()
planSectionRings()
planEnergyPulse()
planFilamentFlow()
planCellularCure()
planSparkConstellation()

SDK 里的：

ts
blueprint.variant = "blueprint" | "rings" | "energy" | "filament" | "cellular" | "spark"

最终会转成一个 uPlanKind 数字，在 shader 里选择分支。

4.5 Triplanar grid ​

网格不是简单用 UV。很多模型 UV 不一定可靠，而且生成模型可能没有好 UV。PLAN C 用 world position 做 procedural grid：

glsl
vec3 grid = abs(fract(worldPos * scale) - 0.5);

再根据法线朝向选择投影平面：

glsl
if (normalAxis.x is largest) use YZ
else if (normalAxis.y is largest) use XZ
else use XY

这就是 triplanar 思路。它的好处是：不依赖模型 UV。

4.6 Rim light ​

轮廓光公式：

glsl
float rim = pow(1.0 - clamp(dot(normalW, viewDir), 0.0, 1.0), 2.2);

当表面法线和视线方向越垂直，rim 越强，所以模型边缘会亮。

4.7 PLAN C 常见难点 ​

  1. z-fighting。

同 geometry overlay 很容易闪，必须处理 polygon offset 或者沿 normal 轻微偏移。项目选择 polygon offset。

  1. 透明排序。

overlay 是透明材质，多个透明层叠时可能出现排序问题。项目通过 renderOrder 和较克制的 alpha 避免明显错乱。

  1. 不要依赖 UV。

生成模型或第三方模型 UV 质量不可控，procedural world-space pattern 更稳。

5. PLAN D：Particle Reconstruct 粒子重构 ​

PLAN D 是三套里最复杂的。它同时做两件事：

txt
1. 原实体 mesh 逐步 dissolve / rebuild
2. 表面星点粒子同步出现 / 消失

也就是说，PLAN D 有两个视觉层：

txt
source mesh patched material
points star layer

5.1 为什么不能只做粒子层 ​

如果只显示粒子，不改实体 mesh，模型永远是完整的，粒子只是贴在上面，无法产生“部件正在被分解”的感觉。

所以 PLAN D 需要让实体 mesh 也按同样进度消失：

txt
实体消失的位置 = 粒子出现的位置
实体恢复的位置 = 粒子收回的位置

这要求两套 shader 共用同一套进度函数。

5.2 统一的 ReconstructState ​

PLAN D shader 里有一个核心状态：

glsl
struct ReconstructState {
  float particleMask;
  float solidMask;
  float frontBand;
};

含义：

  • particleMask：这里应该显示多少粒子。
  • solidMask：这里应该保留多少实体。
  • frontBand：解构/重构前沿高亮带。

计算过程基于一轮循环：

glsl
float cycle = fract(uTime / uCycleDuration);

一轮里分成几个阶段：

txt
0.03 - 0.30  dissolve 前沿推进
0.31 - 0.46  粒子态停留/过渡
0.53 - 0.82  rebuild 前沿推进
0.82 - 0.94  恢复完成

前沿位置：

glsl
float dissolveFront = mix(-softness * 2.0, 1.0 + softness, dissolveProgress);
float rebuildFront = mix(-softness * 2.0, 1.0 + softness, rebuildProgress);

再根据当前点的 coord 和前沿位置算 mask。

5.3 世界空间 build range ​

这是 PLAN D 最容易踩坑的地方。

如果一个部件有多个 mesh，每个 mesh 自己算 uBuildRange，就会导致：

txt
head_A 从底部开始 dissolve
head_B 也从自己的底部开始 dissolve
face 可能不在 head 列表里，完全不动

视觉上就会出现“一个部件被分成多段同时分解”。

正确方式是：

ts
const partBuildRange = getPartBuildRange(allSelectedMeshes)

然后每个 layer 都用同一个 range：

ts
buildRange: partBuildRange.clone()

shader 里也必须使用 world position：

glsl
vec3 worldBase = (modelMatrix * vec4(transformed, 1.0)).xyz;
float buildCoord = clamp((dot(worldBase, uBuildAxis) - uBuildRange.x) / buildRangeSize, 0.0, 1.0);

实体材质 patch 也同理：

glsl
vec3 robotReconstructWorldPosition = (modelMatrix * vec4(position, 1.0)).xyz;

5.4 项目里如何修改实体材质 ​

真实项目没有把实体 mesh 换成一个完全自定义 shader，而是 clone 原材质，然后通过 onBeforeCompile 注入代码：

ts
const clone = material.clone()

clone.onBeforeCompile = (shader) => {
  patchReconstructMaterial(shader)
  applyShaderUniforms(layer, shader)
}

mesh.material = clone

好处是：

  • 保留原来的 PBR 材质、贴图、环境光反射。
  • 只注入 dissolve 逻辑。
  • 退出 PLAN D 时可以恢复原材质。

注入点主要有两个：

txt
#include <begin_vertex>
#include <dithering_fragment>

在 vertex 阶段计算 vReconstructSolidMask，在 fragment 阶段用随机 dither discard：

glsl
if (coverage < dither) {
  discard;
}

这种 dither dissolve 比直接改 alpha 更稳定，因为它可以保留更明确的深度和实体感。

5.5 星点粒子层 ​

PLAN D 的星点粒子也来自表面采样，但 shader 风格和 PLAN B 不同。

PLAN B 是柔和圆点：

glsl
circle point + soft edge

PLAN D 是星点：

glsl
core + body + halo + cross rays

fragment shader 里会用 gl_PointCoord 做一个小星芒：

glsl
float starCore = 1.0 - smoothstep(0.0, 0.22, distanceToCenter);
float starRayX = ...
float starRayY = ...

颜色上：

txt
colors.primary   -> 重构暗部/底色
colors.secondary -> 星点粒子色
colors.accent    -> 前沿高亮色

5.6 PLAN D 常见难点 ​

  1. 原 mesh 和粒子必须同进度。

它们必须共用 build axis、build range、cycleDuration、frontSoftness、frontWidth。

  1. 多 mesh 部件必须用同一个 world-space range。

这是“整体朝一个方向分解/合成”的关键。

  1. 材质恢复要干净。

退出 PLAN D 时必须把原 material、frustumCulled、Points geometry 全部恢复/销毁。

  1. 点大小要补偿 FOV。

PLAN D 也用了和 PLAN B 类似的 point size 补偿，否则切相机时星点大小会忽大忽小。

6. 全身外轮廓光晕：不是描边，而是 screen-space bloom ​

全身外轮廓光晕和 PLAN B/C/D 的边界不一样。PLAN B/C/D 都依赖当前选中的部件；外轮廓光晕是全局效果，只关心“当前机器人整体在屏幕上占了哪些像素”。

视觉目标也不同：它不是一条描边线，也不是给每个部件外面套一个透明壳。参考图里的感觉更接近“模型外轮廓向外散发出淡蓝和淡紫的有色 bloom”，并且蓝紫色里融合了一点白光，所以边界不应该硬。

项目里的实现路径可以拆成三步：

txt
visible robot meshes
  -> mask scene: 渲染一张黑白 silhouette mask
  -> blur pass: 多次模糊 mask，得到向外扩散的软边
  -> composite pass: 排除模型内部，只把外侧 blur 叠回主画面

6.1 为什么不用 BackSide 外壳 ​

很多轮廓光教程会复制 mesh、放大一点、使用 BackSide 材质做外壳描边。这个方法适合卡通描边，但不适合这里的参考效果，原因有三个：

  1. 多部件机器人会出现每个部件各自一圈光，肩膀、手臂、头部之间会互相穿插。
  2. 外壳边缘通常有明确分界，看起来像“包了一圈线”，不是散出来的光。
  3. 如果部件间有缝隙，内部缝隙也会出现光边，破坏“只有整体外轮廓发光”的目标。

所以这里先把所有可见机器人 mesh 合成一张 screen-space mask。mask 是一个统一的整体，后续 blur 出来的就是整体 silhouette 的软光晕。

6.2 Mask pass：只写轮廓，不写真实材质 ​

真实项目里 RobotOuterHaloEffect 会收集当前可见机器人 mesh：

ts
outerHaloEffect.setMeshes(partModelRegistry.getVisibleRobotMeshes())

mask pass 使用和原 mesh 相同的 geometry、matrix 和晶格变形数据，但材质非常简单：只输出白色。

glsl
gl_FragColor = vec4(1.0);

这一步的重点不是“好看”，而是得到一张稳定的二值图：

txt
机器人像素 = 1
背景像素   = 0

如果模型处于晶格编辑状态，mask vertex shader 也要应用同一套 cage delta。否则真实模型已经变形，光晕轮廓还停留在旧形状上，就会明显穿帮。

6.3 Blur pass：弥散范围来自模糊半径 ​

mask 得到后，项目会在较低分辨率 render target 上做多级 blur：

ts
ROBOT_OUTER_HALO_BLUR_LEVELS = [9, 18]
viewer.blur(blurLevel * config.spread, ...)

这里的 spread 就是 SDK 里的“色晕弥散范围”。它不是简单把 mesh 放大，而是改变屏幕空间模糊半径：

  • spread 小：光晕贴近轮廓，边界更窄。
  • spread 大：光晕向外散开，更像雾化 bloom。

低分辨率 blur 有两个好处：性能更稳，也更容易得到柔软的外扩光，而不是锐利描边。

6.4 Composite pass：只保留模型外侧 ​

直接把 blur 贴回屏幕会有一个问题：模型内部也会被一层雾覆盖，尤其头部、胸口等亮面会显得发灰。所以 composite shader 同时读取原始 mask 和 blurred mask：

glsl
float insideMask = texture2D(uRobotOuterHaloMask, vUv).r;
float blurredMask = texture2D(uRobotOuterHaloBlur, vUv).r;
float outsideMask = 1.0 - insideMask;
float exteriorGlow = max(blurredMask - insideMask * 0.86, 0.0) * outsideMask;

这样做的含义是：

txt
blurred mask 负责“散出去的范围”
inside mask 负责“机器人内部不要被糊一层”
outsideMask 负责“只在外侧叠光”

这也是它看起来像 bloom，而不是普通描边的关键。

6.5 蓝紫渐变与白光融合 ​

颜色不是单一色，而是横向渐变。SDK 可以直接传 CSS-like 的 linear-gradient(...)：

ts
robot.setOuterHaloEffect({
  colors: {
    gradient: "linear-gradient(90deg, #DDFBFF 0%, #C8F1FF 15%, #DED0FF 65%, #C4A8FF 100%)",
    highlight: "#FFFFFF",
  },
})

内部会把这条渐变采样成 shader 需要的左右色点：

txt
leftOuter  -> 左侧最外缘冰蓝
left       -> 左侧贴近模型的柔光色
right      -> 右侧贴近模型的薰衣草紫
rightOuter -> 右侧最外缘紫色

bloomStrength 控制白光和有色光的融合程度。它不是再额外画一条白边，而是把高亮色混入已有彩色光晕：

glsl
vec3 bloomColor = mix(haloColor, uHaloHighlightColor, bloomLift * uHaloWhiteMix);

数值太低会显得只是彩色雾，数值太高会变成白边。当前默认值偏向“白光里透出淡蓝淡紫”。

6.6 呼吸灯 ​

呼吸灯只调制合成阶段的强度，不重建 mask，也不改变 blur target 尺寸：

txt
breath.enabled   -> 是否启用
breath.frequency -> 每秒循环次数
breath.intensity -> 起伏幅度

这种做法很轻量，因为每帧只更新 uniform。真正昂贵的部分是 render target 和 blur pass，不能因为呼吸灯每帧创建资源。

6.7 和 PLAN B/C/D 的关系 ​

全身外轮廓光晕是主渲染之后的后处理式叠加层；PLAN B/C/D 是挂在选中部件上的几何或材质层。它们可以同时存在：

txt
主机器人模型
  + PLAN B/C/D selected-part layer
  + outer halo screen-space composite

因此 SDK 里它也不是 setSelectedPartEffect() 的一个 mode，而是独立方法：

ts
robot.setOuterHaloEffect(...)
robot.getOuterHaloEffect()

8. 学习时建议的实现顺序 ​

如果你想从零复刻，不建议一口气写完 B/C/D 和全身光晕。推荐顺序：

  1. 先写表面采样函数。
  2. 用采样点生成最简单的 THREE.Points。
  3. 给点加 normal offset，让它们贴着表面外侧。
  4. 加 aSeed，让每个点有不同闪烁和漂移。
  5. 加 build axis/range，做从一侧推进的显隐。
  6. 做 PLAN B 的 hover。
  7. 做 PLAN C 的 overlay mesh 和 triplanar grid。
  8. 做 PLAN D 的 reconstruct state。
  9. 最后再做材质 patch 或自定义实体 dissolve。
  10. 单独加全身外轮廓光晕：先做 mask pass，再做 blur pass，最后做 additive composite。

这个顺序的好处是，每一步都能在屏幕上看到明确变化。

9. Demo 和项目真实实现的差异 ​

配套 demo 为了易读，做了几处简化：

  • demo 使用基础几何模拟选中部件，不加载真实机器人 GLB。
  • demo 的 PLAN D 实体 dissolve 使用自定义 ShaderMaterial，项目真实实现使用 onBeforeCompile patch 原材质，以保留 PBR 外观。
  • demo 没有接入晶格编辑，所以没有 aCageIndex / aCageWeight 的真实变形流程。
  • demo 的全身外轮廓光晕使用独立 render target + 简化 blur shader；项目真实实现复用 xviewer 的 render target / blur / blit 能力，并同步晶格变形后的轮廓。
  • demo 把 B/C/D 都放在一个 HTML 文件里，便于直接学习；项目中按组件拆分，便于长期维护。

但核心思想是一致的：

txt
PLAN B: surface sampling -> Points -> hover/build/sweep shader
PLAN C: same geometry overlay -> procedural blueprint shader
PLAN D: shared reconstruct state -> solid dissolve + star particles
Outer halo: unified silhouette mask -> blur -> additive gradient composite

10. 最重要的几个坑 ​

坑 1：多 mesh 部件不要各算各的进度 ​

只要视觉目标是“整个部件朝一个方向变化”，就应该用 part-level world range。

坑 2：透明层不要随便 depthWrite ​

粒子和 overlay 通常：

ts
depthTest: true
depthWrite: false
transparent: true

实体 dissolve 则可以使用 discard 保持更明确的深度关系。

坑 3：不要每帧重建 BufferGeometry ​

采样和 geometry 创建应该只在这些情况发生：

  • 切换选中部件。
  • 改变 density / quality。
  • 模型 geometry 发生变化。

每帧只更新 uniform 和 matrix。

坑 4：shader 里要保护 normalize ​

向量长度可能接近 0。项目里很多地方用了 safe normalize：

glsl
float lenSq = dot(value, value);
vec3 normalizedValue = value * inversesqrt(max(lenSq, 0.000001));

否则偶发 NaN 会让粒子直接炸掉。

坑 5：调效果先调坐标，再调颜色 ​

很多看似“颜色不对”的问题，本质是坐标范围错了：

  • buildCoord 是否是 0-1。
  • uBuildRange 是否跨了整个部件。
  • local/world space 是否混用。
  • mesh matrix 是否同步。

坐标错了，后面颜色和透明度怎么调都救不回来。

坑 6：全身光晕不要给每个部件单独套壳 ​

如果把每个部件都复制一份外壳再放大，就会得到很多互相交错的局部光圈。全身光晕应该先把所有可见 robot mesh 合成统一 screen-space mask，再 blur 和 composite。这样才会只保留整体外轮廓的柔光。
